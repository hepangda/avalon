## 模块边界

| 区域 | 现在的职责划分 |
| --- | --- |
| 房间 | [room.ts](../server/room.ts) 保留命令串行化与事务协调；RoomState、RoomMembership、RefereeCommands、RoomViews、RoomCheckpoints、私有 notes 和 wire 分发独立 |
| 认证 | [auth/](../server/auth/) 区分配置、发现/token、流程、会话、加密与校验；discovery 五分钟缓存并合并并发，JWKS resolver 按 URI 复用，失败不缓存且容量有上界 |
| HTTP | [http/](../server/http/) 分为认证、账户和房间路由；只有 Node 入口负责真实数据库/所有权健康检查 |
| 数据库 | [database-schema.ts](../server/database-schema.ts) 管加法式 schema；AccountRepository 管账户查询；房间、回放、扣卡和奖励仍在一个事务中 |
| 游戏引擎 | [events/](../src/lib/engine/events/) 按发牌、提案/发言、任务、结局、回退与日志划分，继续通过同一个 reduce 入口注入时间和随机源 |
| 页面 | GamePage 仅接真实房间；[GameView](../src/components/game/GameView.tsx) 与 PhaseBoard 可被本地画廊共用；正式业务路由延迟加载 |
| 裁判 UI | AdminPanel 负责入口，useRefereeTools 负责状态/动作，RefereeToolDialog 负责表单 |
| 调试 | DebugGalleryPage 负责路由，GallerySession 负责本地引擎，ScenePicker 负责搜索和场景选择；仍被 DEV 边界排除生产 |

WebSocket 升级现在只验证会话并回传刷新 cookie，不再为认证升级顺带读取昵称/偏好或领取每日重随卡。正式账户 session API 继续承担原来的账户显示和奖励行为。

## 保留的兼容和数据

这些是审查报告明确要求满足迁移条件后才能删除的内容，当前仍有真实职责：

- 服务端保留旧客户端推送协议；当前浏览器只使用原子 `view:sync`。
- 账户绑定前的座位/房主 token 兼容仍在，当前账户归属优先。
- flowVersion 1–4 保留用于旧事件回放，当前新游戏仍采用 v5。
- 房间和回放没有新增自动过期策略，没有删除历史记录。
- `.backups/` 和 furry 原图保留；旧 Wrangler 状态与 WAL 整体迁入私有归档，没有丢弃未合并日志。
- 开发配置已从 `.dev.vars` 迁至 `.env.local`，内容逐字一致、权限为 0600。原文件、旧生产变量及旧 Neon 配置保存在 `.private/cleanup-20261002/`，不输出凭据。开发启动器不再读取旧路径。
